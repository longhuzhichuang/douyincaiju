# 第3批-Part1节点实现指南

## 概述

第3批-Part1实现了数据写入层和错误处理层，包含以下功能：
- 视频数据批量写入Google Sheets（27列标准格式）
- 账号统计数据写入Google Sheets（17列）
- 全局错误捕获和智能分类（15列错误日志）

## 节点列表

### Node-019: 写入视频数据到Sheets（Google Sheets Append）
### Node-020: 写入账号数据到Sheets（Google Sheets Append）
### Node-021: 错误日志记录（Error Trigger + Code + Google Sheets）

### 配置步骤

#### 1. 创建Google Sheets Append节点

在n8n中添加节点：
- 节点类型：**Google Sheets**
- 操作：**Append**
- 节点名称：`019: 写入视频数据`

#### 2. 配置参数

```yaml
Authentication:
  - 选择已配置的Google OAuth2凭证
  - 如未配置，点击"Create New Credential"

Document:
  - By: Name
  - Document Name: "抖音视频数据采集"

Sheet:
  - By: Name
  - Sheet Name: "视频数据"
```

### 性能优化

- **批量写入**: 所有视频一次性写入，仅1次API调用
- **写入速度**: <5秒（2000条视频）
- **API配额**: 每次执行仅消耗1次写入配额

### 关键配置说明

#### Auto-Map模式

`Auto-Map Input Data`模式的工作原理：
1. n8n自动读取Sheets表头
2. 将JSON字段名与表头匹配
3. 自动填充到对应的列

**重要**：确保Node-017输出的字段名与Sheets表头完全一致（包括大小写和标点符号）。

#### Continue On Fail

设置为`Yes`的原因：
- 写入失败不会中断整个工作流
- 后续的错误处理节点（Node-021）可以记录错误
- 可以发送失败通知给用户
- 防止50分钟的采集和AI分析工作白费

## Node-021: 错误日志记录

**类型**: Error Trigger + Code + Google Sheets Append
**位置**: 错误处理分支，任何节点失败时触发
**代码文件**: `nodes/node-021b-format-error.js`

### 实现架构

```
任意节点发生错误
    ↓
Node-021-A: Error Trigger（自动捕获）
    ↓
Node-021-B: 格式化错误信息（Code）
    ↓
Node-021-C: 写入错误日志（Google Sheets Append）
```

### 配置步骤

#### 1. Node-021-A: 添加Error Trigger

```yaml
节点类型: Error Trigger
节点名称: "021-A: 错误触发器"

配置:
  # 无需额外配置
  # 自动捕获工作流中任何节点的错误
```

**工作原理**：
- 当工作流中任何节点失败时，Error Trigger自动触发
- 捕获错误信息并传递给下一个节点
- 不影响主工作流的其他分支

#### 2. Node-021-B: 格式化错误信息

```yaml
节点类型: Code
节点名称: "021-B: 格式化错误信息"

代码: 使用nodes/node-021b-format-error.js的代码
```

**核心功能**：

1. **错误分类**（6大类）：
   - 权限问题
   - 网络问题
   - 配额限制
   - 资源不存在
   - 数据格式错误
   - 其他错误

2. **严重程度判断**（4个等级）：
   - **critical**: 致命错误，系统无法继续运行
   - **high**: 严重错误，影响核心功能
   - **medium**: 中等错误，部分功能受影响
   - **low**: 轻微错误，不影响核心功能

3. **智能解决方案建议**：
   - 根据错误类型提供针对性建议
   - 包含具体的修复步骤
   - 根据严重程度添加紧急提示

4. **上下文数据记录**：
   - 记录错误发生时的数据（限制500字符）
   - 便于问题诊断和复现

#### 3. Node-021-C: 写入错误日志

```yaml
节点类型: Google Sheets
操作: Append
节点名称: "021-C: 写入错误日志"

配置:
  Document Name: "抖音视频数据采集"
  Sheet Name: "错误日志"
  Data Mode: "Auto-Map Input Data"
  Continue On Fail: No  # 错误日志写入失败应该停止
```

### Google Sheets表结构

在Google Sheets中创建"错误日志"工作表，包含以下15列表头：

```
错误时间 | 批次ID | 错误节点 | 节点类型 | 错误信息 | 错误代码 | 错误分类 | 严重程度 | 建议方案 | 上下文数据 | 工作流名称 | 执行ID | 是否已解决 | 解决时间 | 备注
```

### 字段说明

| 列名 | 数据类型 | 示例值 | 说明 |
|------|---------|--------|------|
| 错误时间 | 日期时间 | 2025-10-24 09:25:30 | 错误发生时间 |
| 批次ID | 文本 | 2025-10-24-incremental | 所属批次 |
| 错误节点 | 文本 | 019: 写入视频数据 | 出错的节点名称 |
| 节点类型 | 文本 | n8n-nodes-base.googleSheets | 节点类型 |
| 错误信息 | 文本 | The caller does not have permission | 错误消息 |
| 错误代码 | 文本 | 403 | HTTP错误码或API错误码 |
| 错误分类 | 文本 | 权限问题 | 6大分类之一 |
| 严重程度 | 文本 | critical | critical/high/medium/low |
| 建议方案 | 文本 | 检查Google账号权限... | 解决建议 |
| 上下文数据 | 文本 | {"videoId":"123"...} | 错误发生时的数据（限500字符） |
| 工作流名称 | 文本 | 抖音视频采集系统 | 工作流标识 |
| 执行ID | 文本 | 12345 | n8n执行ID（可追溯） |
| 是否已解决 | 文本 | 否 | 是/否 |
| 解决时间 | 日期时间 | | 修复时间（手动填写） |
| 备注 | 文本 | | 处理备注（手动填写） |

### 错误分类逻辑

```javascript
// 权限问题
关键词: authentication, permission, unauthorized, forbidden
示例: "The caller does not have permission"
建议: 检查Google账号权限，重新授权n8n

// 网络问题
关键词: network, timeout, connection, dns
示例: "Network timeout after 30s"
建议: 检查网络连接，稍后重试

// 配额限制
关键词: quota, rate limit, too many requests, exceeded
示例: "Quota exceeded for quota metric"
建议: 等待配额重置或升级套餐

// 资源不存在
关键词: not found, does not exist, no such, missing
示例: "Spreadsheet not found"
建议: 检查文档名、Sheet名是否正确

// 数据格式错误
关键词: invalid, format, parse, malformed, syntax error
示例: "Invalid date format"
建议: 检查数据清洗逻辑和字段格式

// 其他错误
示例: 未匹配的其他错误
建议: 查看详细错误信息，联系技术支持
```

### 严重程度判断逻辑

```javascript
// Critical（致命）
关键词: api key invalid, authentication failed, permission denied, unauthorized
影响: 系统无法继续运行
行动: 立即暂停工作流，修复后再启动

// High（严重）
关键词: write failed, save failed, api error, request failed
影响: 影响核心功能
行动: 在24小时内修复

// Medium（中等）
关键词: timeout, rate limit, slow response, temporary
影响: 部分功能受影响
行动: 记录日志，自动重试，重试失败后通知

// Low（轻微）
其他未匹配的错误
影响: 不影响核心功能
行动: 仅记录日志，定期review
```

## 常见问题

### Q1: Node-019写入失败："The caller does not have permission"

**原因**: Google账号权限不足

**解决方案**:
1. 在n8n中删除旧的Google OAuth2凭证
2. 重新创建凭证并授权
3. 确保授予"Google Sheets"的读写权限
4. 重新测试

### Q2: 部分列为空

**原因**: 字段名不匹配

**解决方案**:
1. 检查Node-017输出的字段名
2. 检查Google Sheets表头
3. 确保完全一致（包括大小写、标点符号）
4. 常见错误：
   - `'视频ID'` vs `'视频id'` (大小写不同)
   - `'视频ID'` vs `'视频ID '` (末尾空格)
   - `'视频ID'` vs `'视频 ID'` (中间空格)

### Q3: 数字列显示为文本

**原因**: 数据类型错误

**解决方案**:
1. 在Node-017中确保数字字段是`number`类型
2. 使用`parseInt()`或`parseFloat()`转换
3. 检查示例：
   ```javascript
   // 错误
   '播放量': '28600'  // 字符串

   // 正确
   '播放量': 28600  // 数字
   ```

### Q4: 日期显示为数字串

**原因**: 日期格式不正确

**解决方案**:
1. 使用标准格式：`YYYY-MM-DD HH:mm:ss`
2. 示例：
   ```javascript
   // 错误
   '发布时间': 1729673430  // 时间戳

   // 正确
   '发布时间': '2025-10-23 14:30:00'  // 格式化字符串
   ```

### Q5: 写入速度很慢

**原因**: 配置了逐条写入或网络问题

**解决方案**:
1. 确认使用`Auto-Map`模式（批量写入）
2. 检查网络连接
3. 查看n8n日志中的执行时间
4. 预期性能：
   - 500条: <2秒
   - 1000条: <3秒
   - 2000条: <5秒

### Q6: Error Trigger未触发

**原因**: 节点设置了`Continue On Fail`但Error Trigger未配置

**解决方案**:
1. 确认Error Trigger节点已添加到工作流
2. 确认Error Trigger的"触发条件"未被禁用
3. 测试：故意制造一个错误，观察是否触发

### Q7: 错误分类不准确

**原因**: 错误信息不包含预定义的关键词

**解决方案**:
1. 查看"错误日志"表中的"错误信息"列
2. 在Node-021-B代码中添加新的匹配模式
3. 示例：
   ```javascript
   // 添加新的错误模式
   else if (msg.includes('your_new_pattern')) {
     return '新的错误分类';
   }
   ```

### Q8: 同一批次数据重复写入

**原因**: 工作流被多次执行

**解决方案**:
1. 检查触发条件（定时触发可能重复）
2. 在写入前添加去重检查（可选）
3. 使用批次ID标识，避免重复处理

## 最佳实践

### 1. 表头命名规范
- 使用中文字段名（便于阅读）
- 字段名简洁明了
- 避免特殊字符
- 统一使用括号（如`互动率(%)`）

### 2. 数据格式统一
- 日期时间：`YYYY-MM-DD HH:mm:ss`
- 布尔值：`是/否`（而非`true/false`）
- 百分比：保留2位小数（如`7.00`）
- 大数字：使用数字类型，Sheets自动格式化

### 3. 错误处理策略
- 关键节点设置`Continue On Fail: Yes`
- 使用Error Trigger集中处理错误
- 错误日志必须写入成功（设置`Continue On Fail: No`）
- 定期review错误日志

### 4. 性能优化
- 使用批量写入而非逐条写入
- 使用Auto-Map而非手动映射
- 限制上下文数据长度（500字符）
- 避免在循环中写入Sheets

### 5. 数据备份
- 定期导出Google Sheets数据
- 使用版本历史功能
- 重要数据考虑多地备份
